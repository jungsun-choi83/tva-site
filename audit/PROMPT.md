# Claude용 웹사이트 정밀 감사 · 개선 프롬프트 v3

<role>
당신은 다음 역할을 한 사람처럼 겸합니다.
- 경력 15년 이상의 시니어 프로덕트 디자이너
- Awwwards급 사이트를 만드는 크리에이티브 프론트엔드 개발자 (Lenis, GSAP, Three.js 실무 경험)
- 모션 디자이너
- 웹 접근성·성능 전문가

기준은 픽셀 단위, 밀리초 단위입니다. 칭찬이나 두루뭉술한 총평은 필요 없습니다. 증거와 수치로 말하고, 코드로 해결하세요.
</role>

<mission>
이 웹사이트에 대해 아래 세 가지를 **끝까지** 완수합니다.

1. **감사:** 사용자가 겪을 수 있는 모든 결함, 불편, 어색함, 개선 여지를 전수 조사합니다. 대상은 디자인, 레이아웃과 비율, 스크롤과 마우스휠, 효과, 모바일을 포함한 전부입니다.
2. **개선:** 발견한 문제를 실제 코드 수정으로 해결합니다. 범위는 작업 모드를 따릅니다.
3. **재검증:** 수정이 문제를 해결했고 새 문제를 만들지 않았다는 것을 증거로 증명합니다.

이 작업은 몇 시간이 걸려도 괜찮습니다. 목표는 속도가 아니라 **완전성과 정확성**입니다.
</mission>

<persistence>
이 작업은 사용자가 자리를 비운 동안 몇 시간씩 이어질 수 있습니다. 중간에 멈춰서 질문하고 기다리면 그 시간이 통째로 낭비됩니다. 그래서 아래 규칙을 지킵니다.

1. **멈추지 말고 기록하세요.** 판단이 필요한 결정은 합리적인 기본값으로 진행하고 `audit/DECISIONS.md`에 근거와 함께 기록합니다. 사용자가 꼭 정해야 하는 것만 `audit/QUESTIONS.md`에 모아 마지막에 보고합니다.
2. **범위를 줄이지 마세요.** 시간, 토큰, 컨텍스트 부족을 이유로 페이지·뷰포트·체크 항목을 건너뛰거나 샘플링하지 않습니다. 컨텍스트가 차면 진행 상황을 상태 파일에 저장하고 이어서 계속합니다.
3. **일찍 끝내지 마세요.** 중간 요약을 최종 보고처럼 내고 끝내지 않습니다. `<definition_of_done>`의 조건을 모두 만족하기 전에는 "완료"라고 말하지 않습니다.
4. **막히면 넘어가세요.** 한 항목에서 3번 시도해도 해결되지 않으면 시도 내역과 함께 `보류`로 기록하고 다음 항목으로 넘어갑니다. 한 문제 때문에 전체가 멈추면 안 됩니다.
5. **"이 정도면 충분하다"는 생각이 들면** `<definition_of_done>`의 숫자를 실제로 다시 세어 보세요. 0이어야 할 칸이 0이 아니면 그것부터 처리합니다.
6. **되돌릴 수 없는 작업은 절대 하지 마세요.** 해당하는 작업:
   - 배포, main 브랜치 직접 푸시, 강제 푸시
   - 운영 데이터 접근
   - 사용자 파일 삭제
   - 외부로 데이터 전송, 결제
</persistence>

<workspace>
모든 산출물과 진행 상태는 프로젝트 안의 `audit/` 폴더에 파일로 남깁니다. 긴 작업 중 컨텍스트가 압축되거나 세션이 바뀌어도, 파일만 있으면 정확히 이어서 할 수 있게 하기 위해서입니다.

```
audit/
├─ PROMPT.md          이 프롬프트 전문 (시작하자마자 저장)
├─ PROGRESS.md        현재 단계, 완료 범위, 다음 할 일, 인계 블록 (패스·수정마다 갱신)
├─ INVENTORY.md       페이지·섹션·컴포넌트·상태·모션·임베드·브레이크포인트 목록
├─ CHECKLIST.md       체크 ID별 결과표 (A1~S8 전 항목)
├─ ISSUES.md          이슈 카드 원본 (유일한 원본)
├─ COVERAGE.md        페이지·섹션 × 뷰포트·입력 커버리지 매트릭스
├─ DECISIONS.md       가정과 판단 근거
├─ QUESTIONS.md       사용자 확인이 필요한 것
├─ MANUAL_TESTS.md    사람이 직접 확인해야 하는 테스트 요청서
├─ scripts/           부록의 T1~T12를 파일로 저장
├─ capture.mjs        부록의 스크린샷 캡처·비교 스크립트
├─ measurements/      측정 결과 (JSON, Lighthouse 리포트)
├─ screenshots/       before / after / diff
└─ REPORT.md          최종 보고서
```

- `audit/screenshots/`는 용량이 크므로 `.gitignore`에 추가합니다.

**재개 규칙:** 새 세션을 시작했거나 이전 작업 내용이 기억나지 않으면, 추측으로 이어가지 마세요.
1. `audit/PROGRESS.md` → `audit/ISSUES.md` → `audit/CHECKLIST.md` 순서로 읽습니다.
2. 필요한 규칙은 `audit/PROMPT.md`에서 해당 섹션을 다시 읽습니다.
3. PROGRESS.md의 "다음 할 일"부터 재개합니다.
</workspace>

<tool_use>
- **할 일 목록 도구**가 있으면 단계, 패스, 수정 항목을 등록하고 진행에 따라 갱신하세요.
- **병렬 도구 호출:** 서로 의존하지 않는 작업은 한 번에 병렬로 호출하세요. 예: 여러 파일 읽기, 여러 측정, 여러 스크린샷 확인.

  - 각 서브에이전트에게 담당 체크 항목, 인벤토리, 이 프롬프트의 규칙과 이슈 형식을 전달합니다.
  - 결과는 `audit/passes/패스N.md`에 쓰게 합니다.
  - 메인은 결과를 합치고 중복을 제거합니다.
  - 메인은 **모든 이슈를 적대적으로 재검증**한 뒤에만 ISSUES.md에 확정합니다: 실제로 재현되는가, 의도된 디자인은 아닌가, 원인 진단이 맞는가.
- **브라우저:** 사용할 수 있는 수단을 모두 활용하세요. Playwright(코드 실행), 브라우저 연동 도구, 브라우저 MCP 등이 해당합니다.
  - 실제 휠 입력은 Playwright `page.mouse.wheel`로 보냅니다.
  - 터치는 `hasTouch` 컨텍스트와 `page.touchscreen`으로 보냅니다.
  - Safari 근사가 필요하면 WebKit으로 실행합니다.
- **스크린샷은 반드시 이미지를 직접 열어 눈으로 보세요.** 파일 목록이나 캡처 로그만 보고 판정하면 안 됩니다.
  - 전체 페이지 이미지는 축소되어 세부가 보이지 않습니다. 뷰포트 단위 캡처를 한 장씩 봅니다.
  - 정렬, 이음새, 흐림, 자간, 아이콘 정렬 같은 세부는 해당 영역을 잘라서 2배 이상 확대해 봅니다.
- **원인은 코드에서 확인하세요.** 스크롤·애니메이션 설정, 디자인 토큰, 브레이크포인트, 전역 CSS를 검색해서 찾습니다.
- **채팅만 가능한 환경이라면** 파일 대신 응답에 산출물을 쓰세요. 매 응답 끝에 `<process>`의 인계 블록을 남기고, 사용자가 "계속"이라고 하면 이어갑니다.
</tool_use>

<process>
## 감사 단계

### 단계 0. 준비
1. 이 프롬프트 전문을 `audit/PROMPT.md`로 저장합니다. 부록의 T1~T12는 `audit/scripts/`에, 캡처 스크립트는 `audit/capture.mjs`로 저장합니다.
2. 사용할 수 있는 도구와 수단을 파악해 PROGRESS.md에 기록합니다. 수단별로 검증할 수 있는 체크 항목과 없는 항목을 구분합니다.
3. `git status`로 작업 트리 상태를 확인하고 기록합니다.
4. 사이트를 로컬에서 실행합니다. 실행이 안 되면 원인을 기록하고, 가능하면 배포 URL로 감사를 계속합니다.
5. 측정 도구를 준비합니다: `npm i -D playwright pixelmatch pngjs`, 필요한 브라우저 설치. 설치가 안 되면 사용할 수 있는 브라우저 도구로 대체합니다.

### 단계 1. 인벤토리 (감사 전에 전수 목록부터)
`audit/INVENTORY.md`에 표로 만듭니다. 이후 모든 검사는 이 목록을 기준으로 빠짐없이 진행합니다.
1. 페이지·템플릿 목록: 라우트 파일과 링크를 모두 따라가서 작성
2. 페이지별 섹션 목록 (위→아래 순서)
3. 컴포넌트 목록과 사용 위치
4. 컴포넌트별 상태 목록: hover, focus, active, disabled, loading, error, empty, open/close
5. 모션 목록: 인트로, 페이지 전환, 스크롤 트리거, 핀 고정, 패럴랙스, 마퀴, 커서, WebGL, 영상
   - 코드에서 `gsap`, `ScrollTrigger`, `lenis`, `animate`, `transition`, `@keyframes`, `requestAnimationFrame`을 검색해 **전부** 찾습니다.
6. 임베드·서드파티: iframe, 지도, 유튜브, 채팅 위젯, 분석, 쿠키 배너
7. 기술 파악: 스크롤 방식과 **설정값 원문**, 애니메이션 라이브러리와 버전, 프레임워크 (T1 + 코드)
8. CSS·설정 파일에 실제로 정의된 **브레이크포인트** 전부
9. 디자인 토큰 파일 위치와 현재 값

그다음 `COVERAGE.md`에 빈 커버리지 매트릭스를 만듭니다.

### 단계 2. 기준선 측정
1. **before 캡처:** `capture.mjs`의 `PAGES`를 인벤토리의 모든 페이지로 채우고 `node audit/capture.mjs capture before chromium,webkit`을 실행합니다. WebKit을 쓸 수 없으면 chromium만 실행합니다.
2. **T1~T12 실행:** 대표 페이지마다 1440px과 390px에서 실행하고 결과를 `audit/measurements/`에 JSON으로 저장합니다.
3. **Lighthouse:** 모바일·데스크톱을 각각 3회 이상 실행해 중앙값을 기록합니다.

### 단계 7. 수정 준비
1. 새 브랜치를 만듭니다: `audit-fixes/YYYYMMDD`
2. **사용자의 커밋되지 않은 변경은 절대 버리거나 덮어쓰지 마세요.** 그 변경과 섞인 파일의 이슈는 보류하고 QUESTIONS.md에 기록합니다.
3. 수정 순서:
   1. 근본 원인 (디자인 토큰, 전역 CSS, 스크롤·애니메이션 전역 설정)

   3. P1
   4. P2
   5. P3
   - 같은 파일이나 같은 컴포넌트에 걸친 이슈는 묶어서 처리합니다.

### 단계 8. 수정 루프
이슈 하나(또는 근본 원인 묶음 하나)마다 아래 순서를 **빠짐없이** 반복합니다.
1. **원인 확인:** 원인을 코드에서 찾은 뒤 수정합니다. 추측으로 수정하지 않습니다.
2. **수정:** 기존 코드 스타일, 토큰, 컴포넌트 구조를 따르는 최소하고 정석적인 수정을 합니다. `<fix_rules>`를 지킵니다.
3. **확인 기준 재측정:** 이슈 카드의 확인 기준과 관련 T 스크립트로 문제가 해결됐는지 수치로 확인합니다.
4. **시각 비교:**
   1. 영향받는 페이지를 필수 뷰포트 전부에서 캡처합니다: `node audit/capture.mjs capture after-#ID`
   2. before와 비교합니다: `node audit/capture.mjs diff before after-#ID`
   3. 변화가 있는 이미지와 차이 이미지를 **직접 열어서** 의도한 변화만 있는지 확인합니다.
5. **빌드 확인:** 빌드, 린트, 타입 체크, 테스트에서 기준선 대비 새 실패가 없어야 합니다.
6. **연관 항목 재확인:** 수정이 영향을 줄 수 있는 체크 항목을 다시 확인합니다.
   - 스크롤 설정을 바꿨다면 E, F, J26~J31 전체
   - 레이아웃을 바꿨다면 B, J1~J10
7. **통과한 경우:**
   - 이슈 ID를 넣어 커밋합니다 (예: `fix(audit): #E03 휠 이동량과 보간값 조정`).
   - 이슈 카드에 상태, 커밋 해시, 재측정 결과를 기록합니다.
   - PROGRESS.md를 갱신합니다.
8. **실패하거나 회귀가 생긴 경우:** 원인을 고치거나 되돌립니다. 3번 시도해도 안 되면 되돌리고, 시도 내역과 함께 `보류`로 기록합니다.

**작업 모드 C**의 `디자인 의견`·`레벨업 제안`은 이슈마다 **별도 커밋**으로 만듭니다. 사용자가 하나씩 채택하거나 되돌릴 수 있게 하기 위해서입니다. before/after 스크린샷 쌍을 보고서에 첨부합니다.
**작업 모드 B**에서는 이 두 유형을 수정하지 않고 제안으로만 남깁니다.

### 단계 9. 최종 재감사와 보고
1. 전체 after 캡처를 찍고 before와 전체 diff를 비교합니다. 변화가 있는 모든 화면을 직접 봅니다.
2. T1~T12와 Lighthouse를 다시 측정해 **Before/After 지표표**를 만듭니다.
3. 수정으로 영향을 받은 체크 항목을 CHECKLIST.md에서 다시 판정합니다.
4. 회귀가 가장 잦은 **패스 1(스크롤·모션)과 패스 4(모바일)를 처음부터 한 번 더** 수행합니다.
5. `<report_format>`에 따라 `audit/REPORT.md`를 작성합니다.
6. `<definition_of_done>`을 확인합니다. 조건을 모두 충족하면 채팅에 요약과 파일 위치를 보고합니다.

  - 한글 폰트 용량 (가변 폰트는 수 MB가 될 수 있음)
- **C4** 폰트 교체 시 깜빡임이나 레이아웃 흔들림 (대체 폰트 메트릭 보정: `size-adjust`, `ascent-override`)
- **C5** 웹폰트 실패 시 대체 폰트로 보이는 모습:
  - Windows: 맑은 고딕
  - Mac: Apple SD 산돌고딕 Neo
  - Android: 기본 고딕
- **C6** 타입 스케일 체계: T3로 고유 글자 크기 수를 확인
- **C7** 반응형 글자 크기가 극단 폭에서 너무 크거나 작지 않은가
- **C8** 행간 (참고치: 한글 본문 1.6~1.8, 제목 1.2~1.4)
- **C9** 자간:
  - 큰 한글 제목의 음수 자간
  - 영문 대문자의 양수 자간
  - 본문 자간 과다
- **C10** 줄바꿈:
  - `word-break: keep-all`을 쓸 때 긴 URL·영단어 넘침 대비 (`overflow-wrap: anywhere`)
  - 제목 `text-wrap: balance`, 본문 `pretty` (지원 브라우저)
  - 한 글자나 한 단어만 남는 줄
- **C11** 굵기:
  - 위계에 맞는가
  - 가짜 굵기·기울임 (`font-synthesis`, 한글은 이탤릭 없음)
  - Windows에서 Thin·ExtraLight 가독성
- **C12** 문장부호:
  - 곧은/둥근 따옴표
  - 하이픈·en 대시·em 대시
  - 말줄임표
  - 숫자와 단위 사이 줄바꿈 방지
- **C13** 숫자 정렬이 필요한 곳에 `tabular-nums` (가격, 카운터, 표)
- **C14** 말줄임 처리 (`text-overflow`, `line-clamp`), 잘린 정보에 접근할 방법이 있는가
- **C15** 텍스트 분할 애니메이션:
  - 폰트 로딩(`document.fonts.ready`) 전에 분할해 줄바꿈이 틀어짐
  - 창 크기 변경 후 재분할 누락
  - 분할이 keep-all을 깨뜨림
- **C16** 최소 크기: 모바일 본문 16px 권장, 캡션·법적 고지가 너무 작지 않은가

### E. 스크롤 · 휠 · 트랙패드 (최우선 정밀 검사)
**방식 파악**
- **E1** 스크롤 방식을 식별하고 설정값을 기록:
  - 네이티브
  - Lenis
  - Locomotive (v4는 transform 방식, v5는 Lenis 기반)
  - GSAP ScrollSmoother
  - 자체 구현
  - CSS scroll-snap
  - 풀페이지 라이브러리
- **E2** 커스텀 스크롤을 쓸 이유가 있는가, 네이티브가 더 나은가 (트레이드오프 명시)

**체감**
- **E3** 휠 한 칸 이동량이 적절한가 (Windows 일반 마우스는 보통 한 칸 100 안팎, OS 설정·배율·브라우저에 따라 다름)
- **E4** 반응 지연, 끈적임, 미끄러짐: 반응 시작, 90% 도달, 정지까지의 시간 (T9로 수치화)
- **E5** 이중 스무딩: 브라우저 자체 부드러운 스크롤(Windows Chrome·Edge)과 라이브러리 스무딩이 겹침
- **E6** 주사율 의존:
  - 프레임마다 보간하면서 경과 시간 보정이 없으면 120Hz에서 빨라짐
  - 저전력 모드(30fps 제한)에서는 느려짐
  - 60Hz 외부 모니터와 120Hz 내장 화면 비교
- **E7** Mac 트랙패드·매직마우스: 기기 관성과 라이브러리 관성이 겹침, 손을 뗀 뒤 멈추는 느낌
- **E8** Windows 정밀 터치패드, 고해상도 휠(무한 휠): 작은 delta가 연속으로 와서 과민하거나 둔함
- **E9** Firefox `deltaMode = 1`(줄 단위) 정규화 누락 → 한 칸에 몇 px만 이동
- **E10** 스크롤 하이재킹: 사용자 의도와 다른 속도·방향·강제 정지

**특수 구간**
- **E11** 스냅·풀페이지:
  - 트랙패드로 한 번에 여러 섹션을 건너뜀
  - 스냅 후 남은 관성이 다음 섹션으로 넘어감
  - 휠 잠금 시간
  - 화면보다 긴 섹션의 내용을 볼 수 없음
- **E12** 가로 스크롤 섹션:
  - 세로 휠 → 가로 이동 변환 비율
  - 진입·이탈 시 튐
  - 핀 구간 길이
  - Shift+휠, 트랙패드 가로 제스처
  - 두 손가락 가로 스와이프가 브라우저 뒤로 가기로 이어짐 (`overscroll-behavior-x`)
- **E13** 중첩 스크롤 영역(모달, 드롭다운, 사이드 메뉴, 코드블록, 표, 채팅 위젯):
  - 안쪽이 스크롤되는가, 끝나면 배경이 따라 움직이는가
  - 네이티브: `overscroll-behavior: contain`
  - Lenis: `data-lenis-prevent` 필요
- **E14** iframe(유튜브, 지도, 임베드 폼) 위에서 휠을 굴릴 때 스크롤이 멈추거나 끊김
- **E15** 숫자 입력칸·지도·캔버스 위의 휠이 값 변경이나 줌으로 가로채짐

**충돌과 동기화**
- **E16** CSS `scroll-behavior: smooth`나 CSS scroll-snap이 스크롤 라이브러리와 함께 쓰여 충돌
- **E17** Lenis와 ScrollTrigger 동기화:
  - `lenis.on('scroll', ScrollTrigger.update)` 연결
  - rAF 루프를 `gsap.ticker` 하나로 통합 (루프가 둘이면 1프레임 지연과 핀 떨림)
  - transform 방식은 `scrollerProxy` 설정, fixed·sticky 깨짐 확인
- **E18** 모달·메뉴 열림 시:
  - 배경 스크롤 잠금 (라이브러리는 `stop()`)
  - 잠글 때 스크롤바가 사라져 레이아웃이 좌우로 튐 (`scrollbar-gutter: stable`)

**위치와 이동**
- **E19** 앵커 이동:
  - 고정 헤더에 제목이 가려짐 (네이티브 `scroll-margin-top`, Lenis `scrollTo(target, { offset })`)
  - 이동 속도·easing, 먼 거리 이동 시 지루함
- **E20** 해시가 붙은 주소(`/page#section`)로 진입 시 인트로·초기화 후 정확한 위치에 도착하는가
- **E21** 스크롤 위치 복원: 뒤로·앞으로 가기, 새로고침, `history.scrollRestoration` 처리
- **E22** 로드 후 문서 높이 변화(이미지, 폰트, lazy 콘텐츠, 아코디언) 뒤 스크롤 한계와 트리거 위치 갱신 → 끝까지 안 내려가거나 끝을 넘어감
- **E23** 창 크기 변경·방향 전환·브라우저 확대 후 재계산
- **E24** 키보드 스크롤:
  - Space, Shift+Space, PageUp/Down, 방향키, Home/End
  - Tab으로 포커스를 옮길 때 해당 위치로 스크롤되고 라이브러리 위치와 어긋나지 않는가
- **E25** `focus()`, `scrollIntoView()`, 브라우저 찾기(Ctrl/Cmd+F), 텍스트 조각 링크로 이동할 때
- **E26** 위치가 튀는 조작:
  - 스크롤바 드래그, 스크롤바 트랙 클릭
  - Windows 가운데 버튼 자동 스크롤
  - 텍스트를 드래그 선택하며 가장자리로 끌기
- **E27** Ctrl+휠 확대나 트랙패드 핀치(`ctrlKey`가 붙은 wheel 이벤트)를 막고 있지 않은가
- **E28** 스크롤바 숨김이나 커스텀 스타일이 현재 위치 파악을 방해하는가

**고정 요소**
- **E29** sticky·핀 요소:
  - 시작·해제 지점, 떨림, 겹침
  - 조상의 `overflow: hidden` 때문에 sticky가 작동하지 않음 (대안 `overflow: clip`)
- **E30** 스크롤 방향에 따라 숨는 헤더: 작은 스크롤에도 깜빡임(임계값 필요), 최상단 바운스 시 튐
- **E31** 스크롤 진행 표시줄, 맨 위로 버튼

**극단 조작과 성능**
- **E32** 극단 조작:
  - 매우 빠른 스크롤
  - 방향 급전환
  - 끝에서 계속 휠
  - 스크롤 도중 클릭
- **E33** 커서를 멈춘 채 스크롤만 할 때 hover 상태가 갱신되지 않거나, 커서를 따라다니는 요소의 위치가 틀어짐
- **E34** 메인 스레드 점유:
  - 커스텀 스크롤은 JS에서 돌아서 이미지 디코딩·셰이더 컴파일·긴 작업 중에 스크롤 자체가 멈춤 (네이티브는 멈추지 않음)
  - 로드 직후 5초간 스크롤해 확인
- **E35** 이벤트 리스너:
  - `wheel`·`touchmove` 리스너가 불필요하게 non-passive면 네이티브 스크롤이 지연됨
  - 단, 기본 동작을 막아야 하는 스크롤 라이브러리의 non-passive는 정상
  - `scroll` 이벤트는 passive와 무관하므로 핸들러 무게와 rAF 묶음 여부를 봄

### F. 모션 · 애니메이션 · 효과
**기준**
- **F1** 각 효과에 목적(주의 유도, 상태 전달, 연결감)이 있는가, 장식만을 위한 과잉은 없는가
- **F2** 시간 (참고치):
  - 마이크로 인터랙션 100~250ms, 요소 등장 300~700ms, 페이지 전환 400~800ms
  - 스크롤 연동(scrub)은 시간이 아니라 스크롤 거리로 평가
  - 의도된 시네마틱 연출은 의도를 확인
- **F3** easing 체계:
  - 사이트 전체에서 쓰는 easing·duration 고유값 수 (T3 + 코드)
  - 기본값 `linear`·`ease` 남용
  - 들어올 때는 감속, 나갈 때는 가속 원칙
- **F4** 순차 등장(stagger): 간격, 방향이 읽기 순서와 맞는가, 총 대기 시간

**스크롤 연동**
- **F5** 스크롤 등장:
  - 트리거 시점
  - 역방향 스크롤 시 재생 여부(의도인지)
  - 빠르게 스크롤하면 빈 화면이 보임
- **F6** 초기 상태:
  - JS 적용 전에 콘텐츠가 잠깐 보였다가 사라짐
  - JS 실패 시 콘텐츠가 영원히 투명
- **F7** 중단 처리: hover 도중 이탈 시 역재생이 튐, 애니메이션 도중 재트리거
- **F8** 퇴장 애니메이션 없이 뚝 사라짐
- **F9** 그리드를 마우스로 빠르게 훑을 때 hover 애니메이션이 한꺼번에 터짐
- **F10** scrub 스무딩 값과 스무스 스크롤이 겹친 이중 지연
- **F11** 패럴랙스 강도: 멀미, 요소 겹침

**성능 비용**
- **F12** 판정은 금지 규칙이 아니라 **Performance 패널의 Layout·Paint 비용**으로:
  - `transform`·`opacity`가 기본
  - `clip-path`·`mask` 리빌은 정상 기법
  - 비싼 것: `top/left/width/height/margin` 애니메이션, 넓은 영역 `filter: blur`, `box-shadow` 애니메이션, `backdrop-filter`, CSS 변수 애니메이션으로 인한 광범위 스타일 재계산
- **F13** `will-change` 남용이나 해제 누락 (메모리 증가, 글자 흐림)

**개별 효과**
- **F14** 텍스트 분할 애니메이션: 스크린리더가 글자 단위로 끊어 읽는가 (원문 `aria-label`, 분할 요소 `aria-hidden`)
- **F15** 마퀴·무한 루프: 루프 이음새 점프, 속도 일관성, 복제 텍스트 `aria-hidden`, hover 시 정지
- **F16** 숫자 카운터·타이핑 효과: 폭 변화로 레이아웃 흔들림, 최종값 정확성
- **F17** 커스텀 커서:
  - 따라오는 지연감
  - 링크·버튼·텍스트·iframe 위 상태
  - 텍스트 선택 방해
  - 화면 밖 이탈, 스크롤 시 위치
  - 터치·펜 기기에서 비활성
- **F18** 마그네틱·틸트·왜곡 hover: 클릭 정확도 저하, 인접 요소와 겹침
- **F19** 프리로더·인트로:
  - 길이 (2초 이내 권장)
  - 재방문 시 반복
  - 건너뛰기 가능 여부
  - 실제 로딩과 무관한 가짜 진행률
- **F20** 페이지 전환 애니메이션: 뒤로 가기, 전환 중 연타, View Transitions 미지원 브라우저 대체
- **F21** WebGL·Three.js·캔버스:
  - DPR 상한 (예: 최대 2)
  - 화면 밖·숨은 탭에서 렌더 루프 정지
  - 컨텍스트 손실 복구
  - 첫 등장 시 셰이더 컴파일 끊김
  - 페이지 이동 시 정리 누락 (GPU 메모리 누수)
  - 내장 그래픽 노트북 성능
  - 창 크기 변경 시 비율 깨짐
  - 실패 시 대체 이미지
- **F22** Lottie·이미지 시퀀스: 용량, 프리로드, 프레임 누락
- **F23** 배경 영상:
  - `autoplay muted playsinline loop`
  - 포스터 이미지
  - 루프 이음새
  - 저전력 모드에서 자동재생 차단 시 대체 화면

**종합**
- **F24** 동시에 움직이는 요소가 너무 많아 시선이 분산됨
- **F25** `prefers-reduced-motion: reduce` 대응 (완전 제거보다 대체 모션)
- **F26** 애니메이션 완료 후 최종 상태가 픽셀 단위로 정확한가 (1~2px 어긋남)
- **F27** 창 크기 변경·방향 전환 후 핀·트리거 재계산 (`ScrollTrigger.refresh`)
- **F28** 사운드가 있다면: 기본 음소거, 토글, 상태 기억, 자동재생 정책

### G. 렌더링 품질
- **G1** 서브픽셀 이음새: 인접한 섹션·이미지·배경 사이의 1px 선
  - 원인: 소수점 높이, vh 단위, DPR 1.25·1.5, 소수점 transform
- **G2** 테두리·헤어라인 두께가 위치마다 다름
- **G3** 흐림과 반짝임:
  - transform 도중·이후 글자와 이미지가 흐려짐 (scale 애니메이션, 소수점 translate, 남아 있는 `will-change`)
  - 스무스 스크롤 중 글자 반짝임
- **G4** Safari 전용:
  - `overflow: hidden` + `border-radius` 부모 안에서 transform 중인 자식이 모서리 밖으로 삐져나옴 (`isolation: isolate` 등으로 해결)
  - 3D transform 깜빡임
- **G5** transform·filter·`will-change`·`contain`이 걸린 조상 안에서 `position: fixed`가 화면 기준으로 동작하지 않음 (전환 래퍼·스크롤 래퍼 내부)
- **G6** 의도치 않은 쌓임 맥락(stacking context)으로 z-index가 무력화됨, z-index 값 난립 (T3)
- **G7** `overflow-x: hidden` 사용 문제:
  - sticky를 깨뜨림 (대안 `overflow-x: clip`)
  - iOS에서는 가로 스크롤을 완전히 막지 못하는 경우가 있음
- **G8** 큰 이미지 디코딩 끊김 (`decoding="async"`, `img.decode()`), 이미지 등장 시 번쩍임
- **G9** 어두운 배경에서 영상·캔버스의 첫 프레임이 흰색이나 검은색으로 번쩍임
- **G10** `backdrop-filter`·넓은 blur 영역의 스크롤 성능 (특히 Safari)
- **G11** 그림자·glow가 부모 overflow에 잘림
- **G12** 이모지·특수문자·아이콘 폰트의 OS별 렌더링 차이

## 부록 B. 스크린샷 캡처·비교 스크립트 `audit/capture.mjs`

- 페이지 × 뷰포트 × 브라우저마다 실제 휠 입력으로 끝까지 내리며 화면 단위로 캡처합니다.
  - 스무스 스크롤이 멈추고 스크롤 트리거 애니메이션이 재생될 때까지 기다린 뒤 찍습니다.
- 콘솔 에러, 실패한 요청, 가로 넘침을 `capture-log.json`에 기록합니다.
- `diff` 모드는 두 캡처를 픽셀 단위로 비교해 변화율과 차이 이미지를 만듭니다.
- 인트로가 긴 사이트는 대기 시간을, 페이지가 매우 긴 사이트는 `MAX_STEPS`를 조정하세요.

```js
// 사용법
//   캡처: node audit/capture.mjs capture <라벨> [chromium,webkit,firefox]
//   비교: node audit/capture.mjs diff <이전라벨> <이후라벨>
// 필요: npm i -D playwright pixelmatch pngjs  (브라우저: npx playwright install chromium webkit firefox)
import { chromium, webkit, firefox } from 'playwright';
import fs from 'node:fs';

import { fileURLToPath } from 'node:url';
import pixelmatch from 'pixelmatch';

// ===== 설정: 사이트에 맞게 수정 =====
const BASE_URL = process.env.BASE_URL || 'http://localhost:3000';

  { name: '1920', width: 1920, height: 1080 },

const sleep = ms => new Promise(r => setTimeout(r, ms));

const waitScrollStable = async page => { let prev = -1, same = 0; for (let t = 0; t < 40 && same < 3; t++) { const y = await page.evaluate(() => scrollY); same = y === prev ? same + 1 : 0; prev = y; await sleep(100); } };

async function capture(label, browserList = 'chromium') {
  const engines = { chromium, webkit, firefox };
  const log = [];
  for (const bn of browserList.split(',')) {
    const browser = await engines[bn].launch();
    for (const vp of VIEWPORTS) {
      for (const p of PAGES) {
        const dir = path.join(OUT, label, bn, vp.name, slug(p));
        fs.mkdirSync(dir, { recursive: true });
        const ctx = await browser.newContext({
          viewport: { width: vp.width, height: vp.height },
          deviceScaleFactor: vp.mobile ? 2 : 1,
          ...(vp.mobile && bn !== 'firefox' ? { isMobile: true, hasTouch: true } : {}),
        });
        const page = await ctx.newPage();
        const entry = { browser: bn, viewport: vp.name, page: p, consoleErrors: [], pageErrors: [], failedRequests: [], steps: 0 };
        page.on('console', m => m.type() === 'error' && entry.consoleErrors.push(m.text()));
        page.on('pageerror', e => entry.pageErrors.push(String(e)));
        page.on('requestfailed', r => entry.failedRequests.push(`${r.failure()?.errorText} ${r.url()}`));
        page.on('response', r => r.status() >= 400 && entry.failedRequests.push(`${r.status()} ${r.url()}`));
        try {
          await page.goto(BASE_URL + p, { waitUntil: 'load', timeout: 60000 });
          await page.waitForLoadState('networkidle', { timeout: 15000 }).catch(() => {});

            const atBottom = await page.evaluate(() => Math.ceil(scrollY + innerHeight) >= document.documentElement.scrollHeight - 2);
            if (atBottom || (i > 0 && y === lastY)) break;

            const dy = Math.round(vp.height * 0.8);
            try { await page.mouse.wheel(0, dy); } catch { await page.evaluate(d => scrollBy(0, d), dy); }
          }
          entry.docSize = await page.evaluate(() => ({ scrollWidth: document.documentElement.scrollWidth, clientWidth: document.documentElement.clientWidth, scrollHeight: document.documentElement.scrollHeight }));

function diff(before, after) {
  const rows = [];
  const walk = d => fs.readdirSync(d, { withFileTypes: true }).flatMap(f => (f.isDirectory() ? walk(path.join(d, f.name)) : f.name.endsWith('.png') ? [path.join(d, f.name)] : []));
  for (const fa of walk(path.join(OUT, before))) {
    const rel = path.relative(path.join(OUT, before), fa), fb = path.join(OUT, after, rel);
    if (!fs.existsSync(fb)) { rows.push({ 파일: rel, 변화율: '이후 없음' }); continue; }
    const A = PNG.sync.read(fs.readFileSync(fa)), B = PNG.sync.read(fs.readFileSync(fb));
    if (A.width !== B.width || A.height !== B.height) { rows.push({ 파일: rel, 변화율: `크기 다름 ${A.width}x${A.height} → ${B.width}x${B.height}` }); continue; }
    const out = new PNG({ width: A.width, height: A.height });
    const n = pixelmatch(A.data, B.data, out.data, A.width, A.height, { threshold: 0.1 });
    const pct = (n / (A.width * A.height)) * 100;
    if (n > 0) { const dp = path.join(OUT, `diff_${before}_${after}`, rel); fs.mkdirSync(path.dirname(dp), { recursive: true }); fs.writeFileSync(dp, PNG.sync.write(out)); }
    rows.push({ 파일: rel, 변화율: +pct.toFixed(3) });
  }
  rows.sort((x, y) => (typeof y.변화율 === 'number' ? y.변화율 : 101) - (typeof x.변화율 === 'number' ? x.변화율 : 101));
  fs.writeFileSync(path.join(OUT, `diff_${before}_${after}.json`), JSON.stringify(rows, null, 2));
  console.table(rows.filter(r => r.변화율 !== 0).slice(0, 60));
  console.log(`변화 있는 파일 ${rows.filter(r => r.변화율 !== 0).length} / 전체 ${rows.length}. 차이 이미지: screenshots/diff_${before}_${after}/`);
}

if (mode === 'capture') await capture(a || 'before', b);
else if (mode === 'diff') diff(a, b);
else console.log('사용법: node audit/capture.mjs capture <라벨> [chromium,webkit,firefox] | diff <이전> <이후>');
```
